# Вход по ПИН-коду на телефоне

После первого успешного входа с телефоном и паролем мастер и исполнитель создают
ПИН-код из ровно четырёх цифр и подтверждают его повторным вводом. Допускается
ведущий ноль. Несовпадающие коды не сохраняются: повторяется только подтверждение.
На шаге подтверждения кнопка «Изменить код» возвращает к созданию ПИН.

При восстановлении сессии и запуске приложения требуется ПИН-код. После успешного
входа с паролем существующий ПИН повторно не запрашивается.
Возврат из фона требует ПИН после 60 секунд отсутствия. Короткий переход в камеру
или другое приложение сохраняет доступ и шаг подтверждения ПИН.
Открытая карточка, диалог или черновик остаются под экраном блокировки.
Переход по push откладывается до разблокировки. Системный запрос разрешения,
который только переводит приложение в `inactive`, временно скрывает содержимое;
Содержимое скрывается сразу при любом уходе с активного экрана. Отсчёт 60 секунд
начинается при первом `hidden`/`paused` и не перезапускается между этими состояниями.

ПИН привязан к адресу сервера и ID учётной записи. После обычного выхода он
сохраняется: повторный вход с паролем открывает тот же аккаунт без дополнительного ПИН.
«Забыли ПИН-код?» завершает сессию. Старый ПИН удаляется только после следующего
успешного входа с паролем в тот же аккаунт, затем создаётся новый. Намерение сбросить
ПИН хранится через `flutter_secure_storage` и переживает перезапуск. Восстановление
JWT и вход в другой аккаунт не разрешают удалить ПИН выбранного аккаунта.

После успешного входа номер телефона сохраняется отдельно от JWT и подставляется
на логине, включая возврат через «Забыли ПИН-код?». Пароль приложение не сохраняет;
поля объединены в `AutofillGroup` для системного менеджера паролей.

## Хранение

SQLite создаётся автоматически через `sqflite`: файл `mineral_pin.db` в приватном
каталоге баз приложения, таблица `app_pins`. Она содержит ключ аккаунта, случайную
соль, HMAC-SHA256, число ошибочных попыток и срок временной блокировки. ПИН в
открытом виде не записывается. Случайный ключ HMAC хранится отдельно через
`flutter_secure_storage` под ключом `mineral.auth.pin.hmac-key`.

После пяти неверных попыток ввод блокируется на минуту. Число попыток и время
блокировки сохраняются в SQLite и переживают перезапуск. Ошибка хранилища или
отсутствие ключа проверки оставляют приложение заблокированным; доступны повтор
попытки и вход с паролем.

ПИН защищает локальный доступ к мобильному интерфейсу; серверная авторизация
сохраняется. При истечении серверной сессии нужен вход с телефоном и паролем.
В веб-версии, на настольных платформах и в деморежиме используется прежний вход.

## Проверка

`flutter test test/pin_repository_test.dart test/pin_lock_test.dart test/login_usability_test.dart` проверяет
реальную SQLite с повторным открытием базы, привязку к аккаунту, временную
блокировку, создание с подтверждением, возврат из фона, сохранение формы,
восстановление через пароль, подстановку телефона, сохранение намерения сбросить
ПИН после перезапуска и защиту от запоздалого результата проверки.

На Android после обновления APK проверьте: вход с паролем → создание/повтор ПИН →
выход на домашний экран → открытие приложения → проверка ПИН → завершение процесса
и повторный запуск. Отдельно проверьте возврат из камеры с незавершённым нарядом.
